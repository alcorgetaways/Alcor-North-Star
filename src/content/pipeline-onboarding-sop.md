# ALCOR GETAWAYS — 9-PIPELINE CLIENT ONBOARDING SOP
## Version 1.0

**Source of truth:** ALCOR 9-Pipeline Activation Tracker v1.0 workbook. This document preserves the workbook's pipeline structure, ownership, target windows, gates, baseline requirements, and task sequence for use inside the Alcor North Star onboarding system.

## How Alcor North Star should use this SOP
- Create one onboarding record/workflow per client.
- Set Day 0 as the date when the signed agreement AND advance have both been received.
- Select the contracted plan and activate only the contracted pipeline modules. P0 Core Onboarding is always active.
- Assign one named Pipeline Manager to each active pipeline.
- Work each pipeline in order: A — Access → B — Inputs → C — Activation → D — Go-Live QC Gate → E — Day-0 Baseline.
- Do not start C before B is complete.
- Every Done status must have evidence: screenshot, Drive file, live URL, or other proof.
- Blocked items must be escalated within 48 hours: Pipeline Manager → Account Manager → Operations Head.
- A pipeline is live only when every D-section Go-Live QC row is Done.
- Tasks marked N/A are out of scope and excluded from task counts.

## Status values
- **Not Started**
- **In Progress**
- **Done** — completed and evidenced
- **Blocked** — escalate within 48 hours
- **N/A** — outside contracted scope

## Core rules
- **One NAP:** P0 creates one exact Name / Address / Phone source of truth. Every pipeline copies it character-for-character.
- **Baseline first:** Capture Day-0 numbers before changing the property setup.
- **Leads need an owner:** Never switch on lead generation without a named person responsible for responding inside the agreed SLA.

# Alcor North Star Implementation Rules

## Service-model logic
### Single Pipeline
If the client purchases one pipeline, activate only that pipeline's task library plus P0 Core Onboarding.

### Funnel / Multi-Pipeline
If the client purchases a multi-pipeline package, activate every pipeline included in the signed scope. The system must allow BD/Admin to add or remove pipelines before activation is finalised.

## Completion logic
A pipeline may be marked **Live** only when every mandatory D — GO-LIVE QC GATE task is **Done**.

The client onboarding may be marked **Complete** only when:
- P0 Core Onboarding Gate is cleared
- All contracted pipeline gates are cleared
- All required evidence is present
- Pipeline Managers are assigned
- Internal handover is complete

## Evidence
Every Done task should support an evidence/link field. Examples include screenshots, Drive files, live URLs, account access confirmation, reports, or approval records.

## Escalation
Any item blocked for 48 hours escalates one level: **Pipeline Manager → Account Manager → Operations Head**.
