# SQL test suites
- SQL suites (supabase/tests/*.sql) are DO blocks that end by raising "PASS …" so every change rolls back. Run them staged: a temporary SECURITY INVOKER runner function (EXECUTE script, return SQLERRM) is created by migration, scripts are loaded into the locked staging table _q69_suites from the sandbox console, and the privileged SQL tool runs `select name, runner(script) from _q69_suites` (suites need auth.users and SET ROLE, so neither the sandbox role nor a SECURITY DEFINER runner works). Then retire the runner by migration and empty the staging table. Why: no permanent arbitrary-SQL entry point.
